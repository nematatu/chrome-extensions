No naked source messages accepted except management. Native local always TRUSTED_CONTEXTS. In content local access use privileged IPC {type:'my-tools:storage',module:id,area,operation,args}, worker allows only config.contentStorage keys (GooglePhotos 2 keys, KLTRA own settings); extension module pages use direct namespaced storage; session not exposed to content. All workers remain available for accepted downloads/status/recovery. New starts/retries/translation/recording types gate on serial settings boundary. Each module client sends readiness notification after page scripts loaded. ## Final observed corrections

The real browser checks found and resolved root-popup bulk authorization, restart-lost menu/badge metadata, MAIN/ISOLATED shared asset injection, and original filename loss caused by the common filename listener. Filename requests are correlated before native callback via a pending canonical URL and after callback via downloadID; starts for the same URL are serialized until ID, other URLs stay parallel. A source filename claim takes precedence; fallback uses the original download options, preserving native conflictAction. Trusted module extension pages route direct downloads through a dedicated root IPC, content does not receive this capability.

An initial three-video fixture passed an AV-mixed MP4 to both independent YouTube tracks; that fixture was invalid for the original converter's separate-track contract. The corrected fixture separates tracks without changing the source converter. The Chromium encoders were actually supported and all three original processors then produced real decodable MP4s. Native download preferences and default behavior are used in the all-module harness because Playwright's download interception bypasses filename determination and masks real paths.

Browser evidence: all-module21 checks, baseline17 checks (Instagram/Gofile/settings/history), source unit415 + combinedunit34. Actual user Chrome and live external services remain unverified. See README for exact remaining feature cases. No original extension installation was removed or disabled.
