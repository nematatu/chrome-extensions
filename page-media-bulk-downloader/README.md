# ページ動画・画像 一括保存

下記の対応サイトの共有ページから動画・画像を、Chromeの保存先の `PageMedia/<フォルダー名>/` へ一括保存する、独立したManifest V3拡張機能です。現行バージョンは **1.8.1** です。リポジトリーのGofile版と同じ一覧上のボタン・1クリックでの保存開始・右下の進捗パネルを使用します。最低Chromeバージョンの設定は111です。サイト別の取得方法と対応形式は後述します。

## 読み込み・更新・使い方

1. Chromeの通常ウィンドウで `chrome://extensions` を開き、デベロッパーモードを有効にします。
2. 「パッケージ化されていない拡張機能を読み込む」で、直下に `manifest.json` がある `page-media-bulk-downloader` を選びます。この環境では `/Users/nematatu/src/github.com/nematatu/chrome-extensions/page-media-bulk-downloader` です。
3. 拡張機能一覧に **「ページ動画・画像 一括保存」・1.8.1** が表示されることを確認します。フォルダー名とは異なる表示名です。
4. 更新の場合は、そのカードの再読み込みボタンを押し、**対象のページも再読み込み**してください。
5. 対象の共有ページの読み込みを待ち、一覧上部の **「動画・画像を一括保存」** を押します。既存サイトはツールバー内、共通形式の10サイトは一覧の見出し内または一覧の先頭に表示します。フォルダーでは現在の階層の一覧を保存します。共通形式の10サイトの個別動画ページでも、その動画が属する一覧を全ページ取得し、直下の動画・画像をすべて保存します。**サイト内の子フォルダーの中身は取得しません。保存する動画・画像は、端末側のサブフォルダー内にまとめます。** HLS動画はMP4へ変換して保存します。
6. 右下の進捗パネルで保存済み件数、全体と各ファイルの進捗を確認します。「残りをキャンセル」は未完了分を停止し、終了後の「失敗分を再試行」は再試行可能な失敗だけを保存し直します。

パネルの×で表示を閉じてもキューは継続します。一覧上の進捗ボタンで再表示でき、ページ再読み込み後も状態を復元します。「完了表示を閉じる」は終了したキューの表示・記録を消去します。保存済みファイルを削除する処理はありません。操作はGofile版と同じく対象ページ内で行います。

ボタンが出ない場合は、通常ウィンドウであること、上記の表示名・バージョン、拡張機能と対象タブの両方の再読み込み、後述の対応サイトの共有ページであることを確認してください。共通形式の10サイトのリンクIDがないトップページ、読み込み中・認証中・期限切れの画面には表示しません。Chromeでサイトアクセスを制限している場合は、利用するサイトと共通APIホスト、HLSでは `vid.fun800.click` へのアクセス設定も確認してください。シークレットウィンドウは使用できません。

読み込みの一次情報: [Chrome公式の導入手順](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-an-unpacked-extension)、[シークレット動作の仕様](https://developer.chrome.com/docs/extensions/reference/manifest/incognito)。

## 保存動作

「サブフォルダー」は、保存先と取得範囲で意味が異なります。

- **端末側の保存先:** すべての動画・画像に `PageMedia/<一覧名>/<ファイル名>` を指定します。Chromeの保存先の直下にファイルだけを並べる指定ではありません。たとえば一覧名が `TestSamples` なら、動画は `PageMedia/TestSamples/video.mp4`、画像は `PageMedia/TestSamples/photo.jpg` を指定します。
- **サイト内の取得範囲:** 開いた一覧の直下の動画・画像を取得します。そこにある子フォルダーへは進まず、その中身は取得しません。これは端末側に保存用サブフォルダーを作らないという意味ではありません。

- 標準の保存先は `Downloads/PageMedia/<ページのフォルダー名>/` です。Chromeの保存先を変更している場合はその配下を使います。既存サイトのフォルダー名はページタイトルの先頭の `Gofile - ` を取り除いた値、共通形式の10サイトではAPIのフォルダー名・チャンネル名を使います。ファイル名は一覧データの値を安全化し、HLSは `.mp4`、直接ファイルで拡張子がない名前には配信URLの拡張子を付けます。危険なパス文字、予約名、制御文字、UTF-8長を制限し、同名ファイルはChromeの連番で保存します。

**1.6.0以前からの更新:** `chrome://extensions` でこの拡張機能の再読み込みボタンを押し、対象ページも再読み込みしてから一覧上部のボタンを押してください。「個別1件・TS保存」や「配信用MP4」の未完了キューは自身の取得・保存をキャンセルし、通常MP4の新しいキューを作り直します。古いキューの「失敗分を再試行」でも一覧を取り直します。旧版のMP4完成通知を新しい保存に使いません。既に保存されたファイルは自動変換・削除しません。
- 保存開始の直前に `PageMedia/<フォルダー名>/<ファイル名>` を確定します。復元キュー・再試行・旧版キューの移行でも、ダウンロード先直下のパスをそのまま使用しません。サブディレクトリを含む相対パスの扱いは [Chrome Downloads APIの仕様](https://developer.chrome.com/docs/extensions/reference/api/downloads#property-DownloadOptions-filename)に従います。
- **1.7.1の保存先修正:** 開始時の `filename` に加え、ブラウザーの `onDeterminingFilename` でも同じサブフォルダーパスを指定します。この拡張機能自身の保存ID、またはIDの確定前に記録したURL・開始時刻・通常ウィンドウの一致を照合し、別の拡張機能や未登録の保存には名前を提案しません。Workerが再起動した場合は保存済みのキューを読み、保存パスを組み直します。最終確定時に上書きできることと、非同期の提案方法は [Chrome公式のファイル名確定イベント仕様](https://developer.chrome.com/docs/extensions/reference/api/downloads#event-onDeterminingFilename)で確認しています。
- 完了はChromeの実際の絶対パスが `PageMedia/<フォルダー名>/` 内にあることも確認してから数えます。名前の連番は許容します。直下・別フォルダーへの保存は失敗表示にし、その一覧の未開始分を止めます。保存先を照会できない一時エラーの間は、完了通知だけで成功にせず、次の状態照会・Worker復旧で確認を続けます。保存済みファイルの削除や、自動での同じファイルの再取得は行いません。
- 旧版の終了済みキューにも保存先の照合を行います。端末側でファイルを移動した後もChromeの履歴は以前のパスを保持するため、その旧キューが保存先不一致になる場合があります。移動済みのファイルを使う場合は「完了表示を閉じる」で旧キューを閉じてください。一覧上の保存ボタンを再び押すと、新しい取得が始まります。
- Gofile版の保存エンジンを独立した拡張機能内へ移植しています。最大10,000件、進行中キュー最大8個、拡張機能全体で同時保存4件までです。同じ一覧での二重開始は既存キューを再利用します。
- 大きなキューも全件を保持し、進捗パネルには失敗・保存中・待機中などを優先して最大100行を表示します。表示から省略した項目も保存対象です。
- 全サイズが判明している間はバイト数で全体の進捗を計算します。サイズ不明を含む場合は項目ごとの進捗へ切り替えます。100%は全件の保存成功だけを示し、失敗とキャンセルは件数を別に表示します。
- キューを項目ごとのlocal storageレコードに分割して保持し、Service Worker停止・再起動後も開始済みのChromeダウンロードに再接続します。保存IDを記録する直前に停止した場合は、自身の拡張機能ID・正確なURL・開始時刻を照合します。複数の候補がある場合は追加保存を止め、候補を並列枠へ数えます。
- キャンセル・再試行の意思も保存します。途中でストレージ書き込みが失敗した場合は、未確定の意思を復元してからキューを進めます。終了したキューの記録は、次の開始・ワーカー復旧時に1時間の保持期間と最大4個の制限に従って整理します。進行中のキューを優先します。

### 1.2.0以前からの引き継ぎ

旧版の進行中・再試行可能なキューがある場合は、元の一覧ページで上部のボタンを押してください。配信URLを現在の一覧と照合し、保存済みID・フォルダー名・キャンセル意思を新版へ引き継ぎます。新版レコードを書き終えるまでは旧版のキューを消しません。元の一覧を照合できない場合は、新たな保存を始めず案内を表示します。終了済みの旧版キューの表示は移植対象外です。

旧版の未完了キューが残っている間は、共通形式の10サイトでも新たな保存を始めません。元の `video.twimg.news` の一覧ページで引き継ぎを完了してください。別のサイトの一覧へ旧版キューを引き継ぐことはありません。

## 対応サイト・制約

製品版の自動表示と保存要求は、以下の11ホストの対応共有ページの**メイン文書だけ**が対象です。他のホスト・iframeからの要求は受け付けません。

| サイト | 許可するページ形式・取得方法 |
| --- | --- |
| `https://video.twimg.news/` | `/d/<数字>/` の埋め込みJSONと画面の一覧を照合 |
| `https://twfiles.com/` | リンクIDを持つ共有ページ。画面の一覧と共通APIの結果を照合 |
| `https://video.twimg1.com/` | 同上。APIの `domain` パラメーターはサイトの公開コードに合わせて `twimg1.com` |
| `https://gofile.run/` | 同上。APIの `domain` パラメーターは `gofile.run` |
| `https://video.twimg-film.com/` | 共通API。`domain=twimg-film.com` |
| `https://cdn4.file-photo.com/` | 共通API。`domain=file-photo.com` |
| `https://gofile.guru/` | 共通API。`domain=gofile.guru` |
| `https://cdn.twimg-image.com/` | 共通API。`domain=twimg-image.com` |
| `https://video.twimg-com.com/` | 共通API。`domain=twimg-com.com` |
| `https://gofile.es/`、`https://gofile.pl/` | `/d/<リンクID>` などの共有ページ。同一サイトの固定 `api.php` で一覧・詳細を取得 |

共通形式の10サイトのURL解析は、公開コードにあるパス末尾のリンクID、末尾の1～8文字の拡張子の除去、長いIDの先頭 `a` の除去、`link` / `externalLinks` クエリに対応します。拡張機能ではIDを英数字・`_`・`-` の160文字まで、パスを2階層までに制限し、アセット・APIのパスや曖昧な重複クエリを拒否します。

### 既存の video.twimg.news

対象サイトでは、インラインスクリプト内の `VIDEOS` JSON配列を読み、画面の `#fl .fm-row .file-name` と件数・名前を照合します。形式変更、読み込み前、部分一覧、不一致、未対応の配信先があれば、部分的な保存を始めずエラーにします。サイトのJavaScriptは実行せず、ページ内のグローバル変数・認証情報は取得しません。

専用収集は **`https://cdn.videy.co/<英数字ID>.mp4`** の配信に対応します。広告リンク、プレビュー画像は保存対象に含めません。このサイトの画像原本の一覧形式は未確認で、専用収集へ追加していません。既存サイトの配信先制限は維持しています。

インラインスクリプトは最大1,000個・合計4Mi文字、一覧は最大10,000項目です。このサイトでは別ページ、無限スクロール、サブフォルダーや他ホストを自動巡回しません。空の `VIDEOS` 配列の実サイト仕様も未確認のため、現状は形式変更として停止します。

### 共通形式の10サイト

ISOLATED worldから、`.landing-content .content-list .video-row` の名前・フォルダー種別と、個別プレイヤーの名前だけを読み取ります。フォルダー記号は `.video-thumb--folder` またはgofile.runの `.video-icon--folder`、個別タイトルは `.player-title h1` またはgofile.runの `.player-summary__copy h1` を使います。画面に表示された項目をAPIの一覧と照合します。1.8.0では各サイトの個別タイトルの `チャンネル名-ファイル名` もAPIの値と厳密に照合します。ページのグローバル変数、Vue内部状態、Cookie、ストレージ、パスワード入力欄は読みません。

gofile.es / gofile.pl以外では、Service Workerが、公開コードで使用されている共通ホスト `https://rwzugqnp.fun800.click` の以下の固定GETエンドポイントへ接続します。送信する値は共有リンクID、サイトのドメイン、ページ番号・ページサイズ・並べ替え設定です。Cookieは `credentials: "omit"`、Refererは `no-referrer` で送信せず、リダイレクトを拒否します。パスワード解除・アクセス数計上・広告・IP取得のAPIは呼びません。

- `/app-api/flow/land-page/getInfo`: 現在の共有ページと、直接配信URLがない同一サイト内のファイル詳細を取得します。
- `/app-api/flow/land-page/list_by_links_page`: フォルダー・チャンネルの現在の階層を20件ずつ取得します。個別動画ページでは、公式アプリと同じ `extraInfo.externalLinks` のチャンネルIDを使います。スクロールで未表示の項目も一覧に含めます。

gofile.es / gofile.plは同一originの `/api.php` を使い、`endpoint=/flow/land-page/getInfo` または `endpoint=/flow/land-page/list_by_links_page` だけを指定します。ページのクエリからAPI接続先を受け付けません。この2サイトの直接MP4・MOVは署名URLの有効期間が600秒だったため、各ファイルの保存開始直前に詳細APIを再取得し、名前とID（双方に存在する場合）を照合してURLを更新します。復元・再試行でも更新し、更新失敗時は古いURLで保存を開始しません。元のMP4・MOVは元形式で保存します。HLSだけを通常MP4に変換します。

APIが返す `netDiskInfo` / `fileInfo`、ページ分割結果の `list` / `records` などを読み、`mp4Url` / `appMp4Url` / `fileUrl` などの配信フィールドから直接ファイルを選びます。相対URLは現在の共有ページを基準に解決します。API由来のドメイン名を持つHTTPS URLで、既知の動画・画像拡張子がある配信に対応します。署名付きクエリも扱います。`localhost`・`.local`・`.home.arpa` などのホスト表記、IPアドレス、独自ポート、資格情報入りURL、広告の遷移先やプレビュー用の `cover` は選びません。直接ファイルの配信先にはhost_permissionsを追加せず、保存はChrome Downloads APIで行います。HLSの配信元は後述の固定ホストだけです。

サイト内の子フォルダーは再帰取得せず、リンクがある場合も中身を取得しません。進捗パネルでサイト内のフォルダー自体を保存対象外として件数表示します。個別動画ページの関連一覧は最後のページまで取得します。別名・別IDの一覧項目は配信URLが同じでも両方を保存し、一覧の件数を減らしません。表示中の動画は一覧にある場合に重複追加しません。広告・プレビューは保存しません。詳細APIにも配信URLがない項目（空欄、null値、確認済みの `https://vid.fun800.click/null`）は「リンクなし」と件数表示し、残る取得可能な項目を保存します。広告やプレビューは代わりに保存しません。未知の配信先・未対応形式、ページ分割の件数変更、重複ページ、画面との不一致、一覧APIの通信失敗では、保存を始めずエラーにします。HLSの形式や断片は各動画の取得時に確認し、不正ならその動画の保存を止めます。`getInfo` による追加のファイル詳細取得は最大1,000回です。

一覧は最大10,000項目・500ページ、API応答は1回1MiB・収集合計32MiBまで、取得1回のタイムアウトは15秒・収集全体は4分までです。APIが総件数を返さず、10,000件ちょうどが20件ずつ続いた場合も、終端を確認できないため停止します。APIのアクセス制限・パスワード要求・期限切れを回避しません。サイト上で解除済みでも、パスワードなしの公開GETで配信情報を取得できない共有は対象外です。

2026年10月10日に確認した一次情報の公開コード: [twfiles.com](https://twfiles.com/assets/index-GmsTj-Nj.js)、[video.twimg1.com](https://video.twimg1.com/assets/index-N-zvpXCi.js)、[gofile.run](https://gofile.run/assets/index-CabAfvLF.js)。APIホスト、GETエンドポイント、ドメインの変換、ページサイズ、データの読み取り方、一覧のDOM構造の根拠です。video.twimg1.comのタイトル結合は同じ公開コードの `U_` 関数と実ページのDOMで確認しました。配信URLに拡張子がない場合や公開コード・APIが変わった場合は、対応できない可能性があります。

### HLS動画（1.7.0で通常MP4と並列取得へ修正）

共通形式の10サイトのAPIが返す `https://vid.fun800.click/` の `.m3u8` に対応します。同じホストの配信一覧と `.ts` 断片だけを、Cookie・Refererなし、リダイレクト禁止で取得します。直接ファイルとHLSの両方がある場合は直接ファイルを優先します。

マスター一覧では最大帯域の画質を選びます。一覧収集時に全動画の配信一覧を先読みせず、各動画の取得開始時に1回だけ読み、最後まで配信済みで暗号化のないTS形式であることを確認します。offscreen文書が1本あたり最大4断片を並列取得し、記載順にTSパケットを検証します。同梱の [mux.js 6.3.0](https://github.com/videojs/mux.js) でH.264映像・AAC音声を取り出し、`mp4.js` がサンプル表・キーフレーム索引・Bフレームの表示時刻・確定した再生時間を持つ通常の **`.mp4`** を作ります。映像・音声の再エンコードは行いません。ライセンスは `vendor/mux.js-LICENSE` に同梱しています。ライブラリーは拡張機能内のファイルを読み込み、遠隔コードは実行しません。HLSの一次情報は [RFC 8216](https://www.rfc-editor.org/rfc/rfc8216) です。

1.6.0では配信用のfragmented MP4をそのまま保存し、動画・音声・ファイル全体の時間を未確定値 `0xffffffff` のまま残していました。[mux.jsの生成コード](https://github.com/videojs/mux.js/blob/v6.3.0/lib/mp4/mp4-generator.js)でも確認できます。MacのAVFoundationでは2秒の合成入力が約27時間と判定され、フレーム抽出が失敗することを再現しました。1.7.0では配信用の `moof/mvex` を保存せず、`mdat` と確定した `moov` のサンプル表へ組み直します。再生時刻の大きな飛び、配信一覧と映像の長さの不一致、欠けたデータはダウンロード開始前にその動画の失敗とします。他の一覧項目は継続します。

映像・音声データは拡張機能専用の[Origin Private File System](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access#accessing_the_origin_private_file_system)の一時ファイルへ順次書き、最後に索引と時間を確定します。動画全体のバイト列をメモリに保持せず、書き終えたファイルをBlobとしてChromeへ渡します。一時ファイル名はランダムな処理IDで、元の名前や配信URLを含めません。保存完了・失敗・キャンセル時に一時ファイルを解放します。拡張機能更新・ブラウザー終了で処理が消えた際の残存ファイルは、次にoffscreen文書を作るときに自身の専用一時領域だけを掃除します。

HLSも拡張機能全体の同時保存4件へ数えます。断片取得を0～90%、Chromeによる保存を90～99%として表示し、保存完了時だけ100%にします。結合後は実データ量をファイルサイズとして表示します。取得中のキャンセルは通信と一時Blobを解放します。通信失敗は手動再試行でき、取得し直す場合は最初からです。Workerだけが再起動した場合は継続中のoffscreen処理と保存IDへ接続します。Chrome終了・拡張機能更新でoffscreen処理が消えた場合は中断表示から再試行してください。

1本5,000断片・映像と音声合わせて100万サンプルまで、受信量・MP4出力量はそれぞれ1GiBまでです。受信・書き込み前のデータとサンプル情報の見積もりは全処理合計512MiBまでです。HLSの動画は同時4本、断片は各4件で最大16リクエストです。配信一覧は1回1MiB、断片は1回16MiB、各取得は30秒・1本の取得全体は1時間までです。配信一覧の探索は最大3階層・各20画質までです。認証・暗号化・ライブ・外部音声トラック・H.264以外の映像・fMP4入力・バイト範囲指定・不連続区間・別ホストの断片は対応対象外です。上限超過や不正な断片では、その動画の保存を止めます。一時保存の容量不足・書き込み失敗は失敗表示にし、手動再試行できます。

受信とBlob作成には `offscreen` と固定配信ホストの権限が必要です。Workerからoffscreen文書へ処理を依頼し、自分の拡張機能のoffscreen文書が返したBlobだけをChrome Downloads APIへ渡します。ページからBlob URLや配信URLを直接指定できません。Blobとoffscreen文書の制約は [Chrome Offscreen API](https://developer.chrome.com/docs/extensions/reference/api/offscreen) に従っています。Chrome 111では `clients.matchAll()` で文書を確認し、116以降は `runtime.getContexts()` を使います。

### 共通の制約

ページ由来のBlob・data URL、DASH、DRM、ライブ配信、再エンコード、独自ヘッダーを要する取得は対象外です。HLSは上記の固定配信ホストと形式だけが対象です。

期限切れ、アクセス拒否、通信失敗などは失敗として表示します。再試行はユーザー操作で行います。動画・画像以外のMIME（例:HTML応答）が判明した項目は保存成功に数えません。返されたファイルが保存先へ残る場合があります。Chromeが危険なダウンロードの確認を求めた場合は自動承認しません。

`downloads` 権限自体はChromeの履歴へ広くアクセス可能ですが、この実装は自身の保存IDを照会し、ID未確定時だけ同じURL・開始時間の候補を検索します。履歴・保存ファイルの削除や危険判定の承認APIは使用しません。

### 1.8.1のHLS変換修正（2026年10月12日）

報告された2種類のエラーを、人物を含まないFFmpegの合成動画で再現し、次を修正しました。報告された14ファイルの中身は取得しておらず、それぞれの失敗原因と修正後の実保存は未確認です。

- **可変フレームレート:** mux.jsが断片の末尾フレーム時間を前のフレームから推定するため、次の断片の実DTSとずれる場合があります。旧処理は2tickを超える差をすべて異常としていました。新版では次のDTSから末尾時間を確定します。映像に限り、既に観測したフレーム間隔の範囲内（最大0.5秒）に収まる場合だけ補正します。AACの丸め許容2tickと、全体の配信時間・欠落・逆行の検証は維持します。
- **音声が先に終わる入力:** remux=trueでは映像と音声がそろうまでmux.jsが断片を出力せず、後半に音声がない正常なTSを拒否していました。新版では映像・音声を別々に受け取り、同じ通常MP4に各トラックのサンプル表を構築します。同じトラックのコーデック定義が途中で変わる入力や、映像がない入力は拒否します。無音の音声データを捏造したり、映像を捨てたりする処理はありません。

実装の一次情報: [mux.jsのframe-utils](https://github.com/videojs/mux.js/blob/v6.3.0/lib/mp4/frame-utils.js)、[Transmuxer / CoalesceStream](https://github.com/videojs/mux.js/blob/v6.3.0/lib/mp4/transmuxer.js)。配信一覧の時間検証は引き続き[HLS RFC 8216](https://www.rfc-editor.org/rfc/rfc8216)のEXTINFに基づきます。

**更新後の再試行:** 拡張機能を1.8.1へ再読み込みし、対象ページも再読み込みします。旧キューが端末内に残っていれば、旧版の `HLS_BAD_SEGMENT` / `HLS_INVALID_TIMELINE` だけを「失敗分を再試行」から再実行できます。更新・状態表示だけでは再取得しません。保存済み項目は再取得せず、同じ保存サブフォルダーと名前を使います。新版で再び同じ形式エラーになった項目を、再起動のたびに自動で再試行可能へ戻すことはありません。記録を閉じた・保持期限を過ぎたキューは復元できません。

合成素材は `tests/fixtures/vfr/`（6秒・154映像フレーム・AAC）と `tests/fixtures/short-audio/`（6秒・180映像フレーム、音声は約2秒で終了）です。FFmpegで両MP4全体をデコードし、VFR入力と出力の154フレームすべての画素ハッシュ一致を確認しました。20時間の開始PTS、断片の順序入れ替え・破損・時刻の飛びを拒否する既存テストも維持しています。
