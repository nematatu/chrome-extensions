# Stripchat ライブ・ホバープレビュー

日本語版Stripchatの一覧カードで、サムネイルにカーソルを合わせている間、サイト標準の公開ライブを無音でプレビューするManifest V3拡張機能です。サイト自身のホバープレイヤーを使い、開始待ちを400ミリ秒、終了時間を無期限（ホバー中のみ）に調整します。

## Chromeへの読み込み

1. デスクトップ版Chrome 116以降で `chrome://extensions` を開きます。
2. 「デベロッパー モード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を選択し、この `stripchat-live-hover` フォルダーを指定します。
4. [対象の一覧ページ](https://ja.stripchat.com/girls/asian)を**再読み込み**します。更新後も、拡張機能を再読み込みしてから対象タブを再読み込みしてください。ページ起動時のスクリプトに適用するため、すでに開いているページには自動で適用されません。
5. サイトの年齢確認・利用規約への同意が必要な場合は、ご自身で内容を確認して操作してください。
6. サイト標準のプレビューが利用できる公開ライブのカードにカーソルを合わせます。

`tests/fixture.html` は合成動画による検証画面です。このHTMLを開くだけでは、Stripchatに拡張機能は読み込まれません。実際のライブで使う場合は、上の手順で `stripchat-live-hover` フォルダーをChromeに読み込んでください。

## 1.0.1での修正

- 実サイトの `main.js` は、設定モジュールを最初から内部テーブルに持っています。起動処理がエクスポートを取得する前に、Webpackのランタイムコールバックでそのテーブルを調整するよう修正しました。後から読み込まれるチャンクにも適用します。
- 検証画面のCSS・JavaScript・動画を相対パスで指定し、合成動画 `tests/demo.mp4` を同梱しました。ファイルを直接開いた場合に、ルートディレクトリの `/core.js` などを探して読み込みに失敗する問題を修正しました。
- Escで停止した動画の取り外しによって、同じカードのホバーが再発生しても再開しないよう修正しました。再試行するにはカーソルを一度カードの外へ移動します。

## 操作と表示

- 約400ミリ秒ホバーすると、その場で無音プレビューを開始します。通信状況によって映像の表示までさらに時間がかかります。
- 実際に動画の再生イベントと再生可能な映像データを確認すると「LIVE · 無音」を表示します。
- カーソルがカードから外れると停止してサムネイルに戻ります。カードを切り替えた場合は、サイト標準の1つのプレイヤーを使います。
- Esc、ウィンドウのフォーカス喪失、タブの非表示でも停止します。Escで止めた場合は、一度カードからカーソルを外して、再び合わせると再試行できます。
- 再生の進行を12秒確認できない場合、または動画要素がエラーを通知した場合は「プレビューできません」と表示します。一度カーソルを外してから再試行できます。
- カードのクリックは通常どおり配信ページを開きます。追加されたカードもイベント委譲で扱います。

## 対応範囲・制約

- 対象ホストは `https://ja.stripchat.com/*` だけです。日本語版以外のホストは対象に含めていません。
- **サイト標準のホバープレビューが利用できることが前提です。** 配信の公開状態、サイトの機能設定、ログイン状況、地域・視聴制限によって再生できない場合があります。
- 年齢確認・規約の同意・認証・プライベート配信・チケット購入の条件は変更しません。サイトが許可していないプレビューを新たに有効化しません。
- サイトの配信にはサイトとCDNへの通信が発生します。取得・再接続は既存プレイヤーが担当し、拡張機能は配信URLや認証データを組み立てません。
- サイト内部のスクリプトとDOMに依存しています。ビルド形式、設定セレクター、カード属性、プレイヤーの構造が変わった場合、継続再生の調整や表示が動かなくなる可能性があります。
- タッチ操作を拡張機能から追加していません。
- 実サイトの年齢確認後のライブ再生と、Chromeで拡張機能として読み込んだ状態の検証は**未実施**です。下記のローカル検証は実サイトでの動作保証ではありません。

## 権限とデータ

追加の `permissions`、`host_permissions`、バックグラウンド処理、ストレージ、外部ライブラリーはありません。日本語版Stripchatだけにcontent scriptを読み込みます。

`MAIN` worldのスクリプトは、ページのWebpackランタイムの初期モジュールテーブルと追加チャンクで、`featuresConfig.features.liveThumbs` を返すセレクターだけを調整します。元の設定オブジェクトを変更せず、`visibilityTimeout` と `duration` だけ変更したコピーを返します。その他のエクスポート、視聴可否の判定、プレイヤー本体はサイトの実装を使います。安定したモジュール番号は前提にしていません。

通常のcontent scriptは、カード内の既存動画要素を監視して状態を表示します。Cookie・トークン・配信URLを読み取りません。カードの識別にDOMのIDとリンクパスをメモリー内で使いますが、ユーザー名や識別子をログや永続ストレージに残しません。ページ側との状態通知には固定値のDOM属性だけを使います。拡張機能独自の外部通信や遠隔コードの読み込みもありません。

## 検証

```sh
node --test stripchat-live-hover/tests/*.test.cjs
node --check stripchat-live-hover/core.js
node --check stripchat-live-hover/native-preview.js
node --check stripchat-live-hover/content.js
```

自動テストでは、元の設定の保持、設定・視聴制限が無効の場合の扱い、初期モジュールテーブル・遅延チャンク、Webpackのpush更新、設定セレクターの参照安定性、無関係なモジュール、URL・ID検証、Manifestと検証画面の同梱ファイルを確認します。初期テーブルの回帰テストは1.0.0で失敗し、1.0.1で成功することを確認しました。

ローカルのブラウザー検証では、製品の `core.js`、`native-preview.js`、`content.js`、`content.css` をそのまま読み込み、検証用のサイトプレイヤーと4秒の合成MP4を使用しました。カード内の無音再生と映像フレームの描画、短時間の既定終了時間を超える継続再生、カード切替、ホバー解除、Esc停止、動的カード、遅延開始の取り消し、視聴不可カードで動画を作成しないことと失敗表示を確認しました。サイトプレイヤーと動画の取得はアダプターであり、実配信や拡張機能の分離worldを検証したものではありません。

合成動画を同梱しているため、ローカルサーバーを起動するだけで検証できます。ファイルとして開く場合は `tests/fixture.html` を開きます。ブラウザーのローカルファイル制限がある場合はHTTPで確認してください。

```sh
node stripchat-live-hover/tests/fixture-server.cjs
```

`http://127.0.0.1:8767/` で各カードや「検証」ボタンを操作し、表示される状態を確認します。

同梱動画はFFmpegで生成した4秒のテストパターンと正弦波です。実配信データは含みません。再生成のコマンドは次のとおりです。

```sh
ffmpeg -hide_banner -loglevel error -y \
  -f lavfi -i 'testsrc2=size=320x180:rate=24' \
  -f lavfi -i 'sine=frequency=440:sample_rate=44100' \
  -t 4 -c:v libx264 -crf 30 -pix_fmt yuv420p -c:a aac -movflags +faststart \
  stripchat-live-hover/tests/demo.mp4
```
