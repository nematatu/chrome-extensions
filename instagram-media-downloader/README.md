# Instagram Media Downloader

Instagramの投稿・ストーリー・リールを保存する独立したManifest V3拡張です。既存の `instagram-high-quality-images` と併用できます。

## Chromeへ読み込む

1. Chromeで `chrome://extensions` を開きます。
2. デベロッパーモードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を押します。
4. この `instagram-media-downloader` フォルダーを選びます。
5. Instagramのタブを再読み込みします。

通常の利用にnpmやビルドは不要です。Chrome 116以降が必要です。更新後は拡張機能の再読み込みボタンを押し、Instagramのタブも再読み込みしてください。

## 画像・動画を保存する

- 通常の投稿表示では、画像・動画の右上にあるピンクの丸ボタンで、現在の1件を保存します。
- プロフィールの投稿一覧では、各サムネイル右上の丸ボタンで、その投稿に含まれる全画像・動画を保存します。一覧には下側の一括保存ボタンを表示しません。投稿を開くと、右上は個別保存に切り替わります。
- 画像の下部にある「投稿を一括保存」で、その投稿のカルーセルをまとめて保存します。まだ表示していない画像・動画も、メディア情報を全件取得できた場合に保存します。通常の投稿表示で利用できます。
- リールの丸ボタンでMP4を保存します。サイドバーから開くリールと、ホームの動画から開く全画面リールが対象です。再生用の `blob:` URLは、投稿情報から配信URLへ解決します。
- ストーリー閲覧画面には個別保存と一括保存の2つの丸ボタンが表示されます。一括保存はそのアカウントの現在取得できるストーリーが対象です。
- ページ全体の一括保存は、拡張のポップアップから実行できます。ページに読み込まれた投稿リンクが対象です。プロフィール全履歴の自動巡回はしません。画面左下の固定ボタンは表示しません。

投稿ボタンは、画像・動画の表示領域を基準に配置します。縦横比、`object-fit`、`object-position`、スクロール、ウインドウ幅、カルーセル切り替えに追随します。ストーリーではヘッダーとの重なりを避けるため、上端から64px下に配置します。

## 保存済みの表示

保存が完了したメディアは、ボタンが緑色とチェックアイコンになります。個別ボタンはその画像・動画、一括ボタンは対象の全メディアを保存できた場合に変わります。個別保存を重ねて全件がそろった場合も、一括ボタンを保存済みにします。緑のボタンを押すと再保存できます。

記録は拡張専用の `chrome.storage.local` に保持し、ページの再読み込みやChromeの再起動後も残します。保存完了を確認できた分だけ記録し、失敗・中止・待機中の分を保存済みにはしません。別タブのボタンも履歴変更を反映します。ストーリー一括は、現在取得した全件の情報で判定します。

更新前にこの拡張で保存した分は、Chromeに残る完了済みダウンロード履歴から初回に取り込みます。履歴が消えている保存、他の拡張や別のChromeプロファイルで保存した分は取り込めません。投稿情報を取得するまで、一括ボタンの判定を確定できない場合があります。

投稿の何件目かを特定できず表示メディアを直接保存する場合は、先頭項目と混同しないよう固有のファイル名を使います。

記録するのはメディア識別子・照合用ハッシュ・保存完了時刻です。期限付きの配信URL、Cookie、アクセストークンは永続保存しません。チェックは保存した履歴を表し、その後にファイルを手動で削除・移動したことまでは追跡しません。拡張を削除すると記録も削除されます。

履歴を書き込めない場合は、ファイル保存の結果と区別して進捗に表示し、記録を再試行します。

## 保存先と進捗

既定の保存先は、Chromeのダウンロードフォルダー内の `Instagram/アカウント名/投稿ID_連番.png` などです。拡張子は画像形式またはMP4です。名前が重複した場合はChromeが別名を付けます。ZIPにはまとめません。

右下に保存済み件数を表示します。Chromeがファイルの保存完了を通知した時点で件数を増やします。失敗したファイルは完了に数えません。

- 一時停止ボタンは、次のファイルの保存開始を止めます。開始済みのファイルの転送は続きます。
- 再開ボタンで、待機中の保存を再開します。
- 中止ボタンで、実行中と未開始の保存を中止します。保存済みのファイルは残ります。
- メディア情報の取得中も中止できます。取得中に別ページへ移動すると、保存開始を中断します。
- 失敗時は元の保存ボタンを押して再実行できます。失敗のあるジョブの再実行では、メディア情報を取り直します。一括保存の再実行は、その一括対象全体を保存し直します。

同じタブでは1つの保存処理が動きます。ページ一括は100投稿まで、保存キューは全タブ合計500ファイルまでです。URLの合計長にも上限があります。Chromeの「ダウンロード前に各ファイルの保存場所を確認する」などの設定は、Chrome側の動作に影響します。

## 権限と通信

| 権限・対象 | 用途 |
| --- | --- |
| `downloads` | ファイル保存と完了・失敗・中止の確認 |
| `storage` | ワーカー停止に備えたキューの一時保存と、保存済み履歴のローカル永続保存 |
| `alarms` | ワーカー再起動後のキューの照合と再開 |
| `https://*.cdninstagram.com/*`、`https://*.fbcdn.net/*` | Instagram配信CDNからの画像・動画保存 |
| `https://www.instagram.com/*` のcontent script | 保存ボタンの表示と閲覧中のメディア情報取得 |

メディア情報は、現在ログインしているInstagramの `/graphql/query` に読み取りクエリを送って取得します。ページが取得したJSON応答も観測します。セッション内のCSRFトークン等はInstagramへの同一オリジンの読み取りにだけ使用し、保存・ログ出力しません。外部のダウンロード代行サーバーは使いません。

待機中と実行中のCDN URL、保存名、ダウンロードIDを `chrome.storage.session` に一時保存します。完了・失敗・中止したファイルのURLは削除します。状態はブラウザー再起動をまたいで保持しません。ダウンロード履歴自体はChromeの管理対象です。ワーカー再起動時はChromeの実際の保存状態と照合します。

## 対応範囲と制約

- 閲覧権限のあるコンテンツが対象です。ログイン、フォロー状態、公開範囲の制限を迂回しません。
- ストーリーの期限切れ、CDN URLの期限切れ、削除済みコンテンツ、Instagramのアクセス制限で保存できない場合があります。
- 429応答は中断して表示します。無制限の自動再試行はしません。
- Instagramの非公開API、クエリID、HTML構造に依存します。仕様変更やアカウントごとの差による失敗はあり得ます。
- 元解像度の保証はしません。取得できた画像・動画候補のうち、画素数が最大の候補を選びます。URLのパラメーターを書き換えて高画質化した扱いにはしません。
- 全メディアを取得できない投稿や、続きがあると明示されたストーリーは一括保存を中断します。
- 動画のURLが解決できない場合、動画の代わりにサムネイルを保存しないよう、プロフィールの画像へのフォールバックを制限しています。
- DM、Liveの録画、音声のみの保存、DRM、DASH断片の結合は対応していません。
- 他のInstagramダウンロード拡張と併用するとボタンが重なる場合があります。他の拡張のUIは変更しません。

## 検証する

単体テストはNode.js 20以降で実行できます。

```sh
npm test
```

ブラウザーテストにはPlaywright、Chromium、OpenSSLが必要です。

```sh
npm ci
npx playwright install chromium
npm run test:browser
```

ブラウザーテストは一時プロファイルに実際の拡張を読み込み、Instagramの画面・JSON応答とローカルHTTPS配信CDNを再現します。証明書の検証免除とローカル配信への許可は、この一時テスト用ブラウザーだけに適用します。通常のChrome設定は変更しません。

実ファイルの保存、画像右上の座標、カルーセル、blob動画の解決、ストーリー、一時停止・再開・中止、取得中の中止と画面遷移、404・429、サムネイル誤保存防止を検証します。結果と画面は `test-results/` に生成します。MP4のfixtureはFFmpegで生成した0.5秒の単色映像とテスト音です。

実施済みの検証と未検証範囲は [VERIFICATION.md](VERIFICATION.md)、設計・UI参照は [DESIGN.md](DESIGN.md) に記録しています。
