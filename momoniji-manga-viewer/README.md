# Momoniji 漫画ビューア・一括保存・後で読む

Momoniji の作品ページを開くと、漫画を右綴じのビューアで表示する Chrome 拡張機能です。作品が複数の Web ページに分かれていても、同じ作品のページを集めてから表示します。一覧・ランキングページでは起動しません。

## Chrome に読み込む

1. `chrome://extensions` を開き、「デベロッパー モード」を有効にします。
2. 「パッケージ化されていない拡張機能を読み込む」を選択します。
3. このディレクトリ内の **`extension` フォルダ**を選択します。
4. Momoniji の作品ページを開きます。既に開いているタブは再読み込みしてください。

Chrome 120 以降を対象としています。拡張機能のソースを更新した場合は、拡張機能管理画面で再読み込みし、作品タブも再読み込みしてください。拡張機能の利用には npm やビルド操作は不要です。

## 読む

- 初期表示は右綴じの横読みです。横長のウィンドウでは見開き、縦長では 1 ページ表示になります。表紙は単独で表示します。
- 左側のクリック・スワイプ・矢印キー・スペースキーでページを送れます。ページスライダーで指定の位置へ移動できます。
- ビューアの拡大ボタン、ダブルクリック、ピンチ操作で拡大できます。
- 上部の「横読み・見開き／縦読み」「右綴じ／左綴じ」で表示方法を変更できます。
- 「元のページ」、ビューアの戻るボタン、Esc で元のページへ戻れます。拡大中の Esc は先に拡大を解除します。
- 元のページにも「漫画ビューアを開く」「全 N ページを一括保存」の操作パネルが残ります。
- 読書位置は作品ごとのキーで、そのサイトの localStorage に記録されます。再訪時には OSS ビューアが「続きから読みますか？」を表示します。サイトデータを削除すると記録も消えます。

## 後で読むと保存済み表示

v1.1.0 では、Momoniji の漫画・作品リンクを右クリックして **「この漫画を後で読むに保存」** を選べます。作品を開かず、一覧の作品リンクからも登録できます。画像そのものの URL を登録するのではなく、リンク先の作品ページを確認して作品名・作品 URL を記録します。漫画以外のページや外部リンクは登録しません。

拡張機能アイコンから一覧を開き、検索、未読／読了の切替、削除、削除直後の「元に戻す」を操作できます。一覧の下部では現在の作品を追加できます。作品を開くだけでは読了にせず、読了は明示的に切り替えます。件数が多い場合は 100 件ずつ表示し、検索は全件が対象です。

作品ページと漫画ビューアには「後で読む」ボタンを表示し、登録すると「後で読むに保存済み」に切り替わります。一覧の作品リンクにも登録済み表示を付けます。同じ作品の続きページ、URL のクエリ・フラグメント、`www` の有無は同じ作品として扱い、再登録で重複させません。拡張機能アイコンのバッジは未読件数です。

**「後で読むに保存済み」と「画像ダウンロード済み」は別の状態**です。一括ダウンロードの全ページ完了時は、作品 URL・タイトル・枚数・保存先・日時を独立した履歴に記録します。後で読むから外しても、この履歴は保持します。サイトの一覧・作品ページ・ビューア・ポップアップで確認できます。これは過去の保存完了の記録であり、現在もファイルが存在することを保証する表示ではありません。

記録先は拡張機能専用の [`chrome.storage.local`](https://developer.chrome.com/docs/extensions/reference/api/storage) です。Cookie の有効期限やサイト側の localStorage に依存せず、サイトデータ削除・サービスワーカー再起動・Chrome 再起動後も保持します。同じブラウザプロファイルに保存し、外部サービスへの送信や別端末への自動同期は行いません。拡張機能のアンインストールや拡張機能自身のデータ削除では記録が消えます。

後で読む・画像保存履歴の合計で最大 5,000 作品、記録用 JSON は最大 4 MiB です。上限や保存失敗時はエラーを表示し、既存の記録を自動削除したり、保存できていない作品を保存済みと表示したりしません。画像ダウンロードの短期キューとは別に保持するため、キュー履歴の 8 作品制限では消えません。更新前の完了済みキューに残っている作品は履歴へ移行しますが、既にキューから除外された過去の作品は復元できません。

UI は [Raindrop.io](https://help.raindrop.io/bookmarks) の検索・一覧・保存済み表示と、[Chrome リーディング リスト](https://support.google.com/chrome/answer/7343019?hl=ja&co=GENIE.Platform%3DDesktop) の未読／読了・行内操作を参考にしています。確認した利用者数・公開画面・実際に採用した要素を `UI-REFERENCES.md` に記録しています。

## 一括保存する

ページ内の **「全 N ページを一括保存」**を押すと、Chrome のダウンロード先の中へ、次の構成で画像を保存します。

```text
ダウンロード/
└── momoniji-manga-viewer/
    ├── 作品名-作品URLから生成したID/
    │   ├── 0001.webp
    │   ├── 0002.webp
    │   └── ...
    └── 別の作品名-別のID/
        └── ...
```

画像形式は元の画像を維持します。ページ番号は作品全体での順序です。タイトル内の保存先に使えない文字を置換し、同名作品も URL 由来の ID で分けます。個々の画像ファイルを保存する方式で、ZIP 圧縮はしません。

進捗は Chrome が画像の保存を完了した枚数です。2 枚ずつ保存し、一時的なネットワーク障害は最大 3 回まで試します。「保存を中止」で停止でき、「失敗・中止ページを再試行」では失敗・中止したページだけ再開します。保存済み画像は再試行の対象になりません。もう一度「全 N ページを一括保存」を押すと新しい保存を開始し、同名ファイルは Chrome が別名にして既存ファイルを保護します。

タブを閉じても保存キューはバックグラウンドで継続します。キューは拡張機能のストレージへ記録し、サービスワーカーの再起動後は Chrome のダウンロード状態を照合します。作品を再訪すると進捗表示を復元します。

保存先は Chrome の既定のダウンロードフォルダを基準にします。v1.0.1 から新しい保存は専用の `momoniji-manga-viewer` フォルダ内に作成します。更新前に記録したキューの再開では元の保存先を維持します。新しい専用フォルダへ保存するには、既存の保存が終了した状態で「全 N ページを一括保存」を押してください。

Chrome 側で「ダウンロード前に各ファイルの保存場所を確認する」を有効にしている場合など、ブラウザの設定・管理ポリシーが保存の挙動に影響することがあります。この拡張機能は自分の保存処理にだけ作品フォルダを指定し直しますが、別の拡張機能のファイル名変更処理が優先される場合があります。Chrome の仕様では、複数の拡張機能がファイル名を提案すると最後にインストールされた拡張機能の指定が採用されます（[Chrome の公式説明](https://developer.chrome.com/docs/extensions/reference/api/downloads#event-onDeterminingFilename)）。

指定した作品フォルダ以外へ保存された場合は、「保存先が指定した作品フォルダと異なります」と表示します。保存先を変更する拡張機能や Chrome の保存設定を確認した後、「失敗・中止ページを再試行」で指定フォルダへ保存できます。異なる場所に保存されたファイルは削除しません。

日本語の濁点などで Unicode の内部表現が異なる同じファイル名は、同じ保存先として照合します。更新前に「保存情報が一致しません」となったページの再試行時も、既に正しい場所へ保存されたファイルは完了として再確認し、重ねて保存しません。

## 対応範囲とエラー表示

- 対象の Web ページ：`https://momoniji.com/`、`https://www.momoniji.com/`。
- 対象の画像：上記ホストと `img.momoniji.com` の HTTPS JPEG／PNG／WebP／GIF／AVIF。
- 現在のサイト構造である `#cif .iw img` の `c1` 等のページ番号、`#content` の作品 ID、作品のページリンクを利用します。
- 全ページ数は「1-40ページ」「41-43ページ」等のページ案内を検証して取得します。範囲が連続し、現在ページの位置、同作品へのリンク、上下の案内が一致する場合に限り使用します。サイトの作品情報表が空欄・古い枚数でも、この案内で全画像を照合できます。
- 数字付きのページ案内がない旧形式では、作品情報表の全ページ数を利用します。情報が最初の Web ページだけに載る構造に対応し、続きから開いた場合も最初のページを取得して照合します。
- 1 作品 1,000 枚、100 Web ページ、HTML 1 ページ 4,000,000 文字、画像 URL 長 2,048 文字、画像 URL 列の総文字数 300,000 文字を上限にしています。キューは同時に最大 3 作品、保存処理全体の並列数は 2 です。
- 全ページ数に対する欠落、重複、別作品、取得失敗を検出した場合、一括保存を有効にしません。「再取得」で再試行できます。
- サイト側の構造変更、画像削除、ログイン・アクセス制限、ネットワークや Chrome の保存制限で失敗する場合があります。画像の取得が成功することを常に保証するものではありません。

## 権限とデータ

| 指定 | 使用目的 |
| --- | --- |
| `downloads` | 作品別の保存先・ページ番号を指定した画像保存、完了状態の確認、中止 |
| `storage` | 保存キューと再開に必要な画像 URL・状態、後で読む一覧・画像保存履歴を拡張機能内で記録 |
| `contextMenus` | Momoniji 内の右クリックから作品を後で読むへ追加 |
| `alarms` | サービスワーカー停止後の状態照合と、一時障害時の再試行 |
| `host_permissions` の Momoniji 2 ホスト | 同じ作品の残りの Web ページを取得 |
| `content_scripts.matches` の Momoniji 2 ホスト | 作品検出とビューア・操作パネルの表示 |

ビューア本体はローカル同梱します。CDN から実行コードを読み込みません。拡張機能が独自に通信する相手は対象サイトと画像ホストです。解析サービスや外部の保存サーバーへ送信する処理はありません。

保存キューの画像 URL は復旧のために `chrome.storage.local` に保持し、コンテンツスクリプトからの直接アクセスを許可しません。最大 8 作品を保持し、キューが埋まると終了済みの古い作品から除外します。元の Web ページが行う通信や表示は、そのサイト自身の挙動です。

後で読むと保存履歴も同じ拡張機能ストレージの別キーに記録します。サイトのスクリプトにはストレージを公開せず、拡張機能のメッセージを検証して操作します。ポップアップ一覧はリモートの表紙画像を取得しません。登録時の作品確認と、保存作品を開く操作では対象サイトへアクセスします。

## 採用した OSS

[`@tokagemushi/manga-viewer` v0.6.0](https://github.com/tokagemushi999/manga-viewer/tree/db5d7c8174c00db839795e3cf8b477a0d6431430) を使用しています。MIT ライセンス、ランタイム依存なし、Shadow DOM によるスタイル分離、右綴じ・見開き・拡大操作が組み込みに適しているため採用しました。

`extension/vendor/` に原本、MIT ライセンス、固定コミット・SHA256 を記録した `provenance.json`、原本との差分を含めています。変更は content script 用の IIFE 化と、非表示の任意ボタンへイベント登録した際の例外を避ける null チェックです。

## 開発・検証

Node.js 24 で検証しています。

```sh
npm ci
npx playwright install chromium
npm test
npm run test:browser
npm run test:filenames
npm run test:recovery
npm run test:library
```

ブラウザテストは専用の一時プロファイルとローカル HTTPS サーバーを使い、合成漫画画像で実際の Manifest V3 拡張と Chrome のダウンロード API を検証します。既存の Chrome プロファイルやダウンロード先には書き込みません。一時 HTTPS 証明書の生成には `openssl` が必要です。

実サイトの検証は別スクリプトで実行します。対象 URL を指定した場合のみ実サイトへアクセスします。実サイトの画像・URL・タイトルはテストの出力へ表示せず、画像は一時フォルダで技術的に検証し、終了時に削除します。

```sh
MOMONIJI_LIVE_URL='対象作品のHTTPS URL' node tests/live.cjs
```

既定では DOM と画像の読み込みを確認します。`MOMONIJI_LIVE_DOWNLOAD=1` を加えると 1 枚、`MOMONIJI_LIVE_DOWNLOAD=all` ではページ内のボタンから全枚数を一時フォルダへ保存し、実際の作品名による保存先・完了状態・画像の識別情報を確認して削除します。`MOMONIJI_LIVE_EXPECTED_PAGES` を指定すると、期待する全ページ数との一致も確認できます。

後で読むの実サイト検証は、画像・ページのスクリプト・無関係な通信を遮断し、同じ作品の HTML だけを取得します。登録、重複防止、作品とポップアップの保存済み表示、ページ再読み込み後の保持を確認し、専用プロファイルは終了時に削除します。

```sh
MOMONIJI_LIVE_URL='対象作品のHTTPS URL' npm run test:library:live
```

検証範囲と結果は `TESTING.md` を参照してください。
